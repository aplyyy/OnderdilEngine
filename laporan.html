4. PENJELASAN APLIKASI & PROFIL MITRA (PT ANUGRAH MOTOR)

A. Profil Mitra & Latar Belakang Proyek

Aplikasi ShiftGear (OnderdilEngine) dibangun berdasarkan hasil observasi dan wawancara awal pada tanggal 19 Oktober 2026 bersama Mang Acim selaku pemilik Bengkel Anugrah Motor (PT Anugrah Motor) yang berlokasi di Jl. Syeh Maulana Akbar No.88, Kuningan, Kec. Kuningan, Kabupaten Kuningan, Jawa Barat 45511 (No. HP: 081324735850). Bengkel ini memiliki kegiatan utama melayani servis berkala kendaraan, penjualan suku cadang, dan pengelolaan antrean pelanggan dengan jumlah pengguna operasional sebanyak 12 orang (1 Pemilik, 1 Kasir, dan 10 Mekanik). Sarana TIK yang tersedia adalah 1 unit PC/Laptop di meja kasir dengan koneksi Wi-Fi serta perangkat smartphone Android yang digunakan oleh para mekanik.

Sebelum adanya sistem ini, proses pendaftaran pelanggan, penugasan montir, pemakaian suku cadang, dan pembayaran kasir masih terpisah serta mengandalkan nota kertas manual. Hal ini menimbulkan kendala nyata di lapangan: antrean kendaraan menumpuk saat akhir pekan, riwayat perbaikan mobil/motor tidak terlacak, serta ketersediaan fisik sparepart sering tidak sinkron dengan catatan kasir. Oleh karena itu, platform ShiftGear / OnderdilEngine hadir sebagai solusi terpusat yang aman, cepat, dan terintegrasi untuk mengotomatiskan seluruh alur operasional bengkel mulai dari antrean servis hingga pembayaran kasir dan rekapitulasi finansial.

C. Fitur Utama Sistem

  1. Autentikasi & Kontrol Akses (RBAC): Sistem memisahkan tiga hak akses pengguna, yaitu Administrator, Kasir, dan Mekanik. Kata sandi disimpan menggunakan fungsi hash bcrypt. Sesi login dikelola menggunakan token JWT yang disimpan di dalam cookie berstatus HttpOnly dan Secure agar tidak bisa dibaca oleh script JavaScript peramban.
  2. Transaksi Kasir POS & Cetak Nota Resmi: Kasir dapat mencari suku cadang dengan cepat, menambahkan barang ke keranjang belanja, menggabungkan biaya jasa servis montir, menghitung diskon dan nominal kembalian, serta mencetak nota pembayaran (faktur) resmi atas nama Bengkel Anugrah Motor dalam format thermal receipt.
  3. Alur Kerja Antrean Servis (Kanban Board): Halaman montir menampilkan tahapan kendaraan mulai dari status Menunggu, Sedang Dikerjakan, hingga Selesai. Montir dapat menuliskan catatan perbaikan dan memilih suku cadang yang dipasang, yang secara otomatis akan mengurangi stok barang di gudang secara real-time.
  4. Master Data Suku Cadang (CRUD): Pengelolaan data barang meliputi kode SKU, nama barang, kategori, harga modal, harga jual, dan jumlah stok fisik. Sistem dilengkapi penanda stok menipis (Low Stock Alert) jika persediaan barang berada di bawah batas minimum (5 unit).
  5. Laporan Penjualan & Ekspor CSV: Rekapitulasi transaksi kasir menampilkan total omzet, pendapatan suku cadang vs jasa montir, serta fitur unduh laporan transaksi ke berkas CSV / Excel.

D. Arsitektur dan Teknologi yang Digunakan

  • Framework Utama: Next.js versi 15 (App Router) berbasis runtime Node.js v24 dan bahasa pemrograman TypeScript.
  • Basis Data & ORM: SQLite untuk lingkungan pengembangan lokal dan PostgreSQL untuk lingkungan server produksi, dikelola melalui Prisma ORM yang secara otomatis menggunakan Parameterized Queries.
  • Kriptografi & Manajemen Sesi: Modul bcryptjs untuk hashing kata sandi dan modul jose untuk pembuatan serta verifikasi cryptographic signature token JWT.
  • Validasi Input: Pustaka zod untuk memastikan tipe data yang dikirimkan ke server sesuai dengan skema yang diizinkan.
  • Antarmuka Pengguna: Tailwind CSS v4 dengan tata letak dashboard sidebar profesional bertema bengkel otomotif modern.
  • Keamanan HTTP: Next.js Edge Middleware untuk memasang HTTP Security Headers seperti Content-Security-Policy (CSP), X-Frame-Options, dan X-Content-Type-Options.

Penerapan kontrol keamanan pada kode program dirangkum pada tabel berikut:

Mekanisme Keamanan Letak Komponen / Berkas Tujuan & Alasan Penerapan

JWT HttpOnly Cookie src/lib/auth.ts Mencegah pencurian token otentikasi kasir melalui serangan XSS karena cookie tidak dapat diakses lewat JavaScript peramban.

Rate Limiting src/lib/rate-limit.ts Membatasi percobaan login maksimal 5 kali dalam 1 menit per alamat IP guna menahan serangan brute-force.
Sanitasi Input (Anti-XSS) src/lib/security.ts Mengubah tag HTML pada catatan keluhan konsumen menjadi entitas karakter aman agar script peramban tidak dijalankan.
Security Headers src/middleware.ts Memasang header X-Frame-Options: DENY untuk mencegah serangan clickjacking serta nosniff untuk mencegah MIME-sniffing.
Penyembunyian Rahasia .gitignore, .env.example Memastikan file .env yang berisi kunci rahasia tidak pernah terunggah ke repositori GitHub.
5. POTENSI PENGEMBANGAN SEBAGAI TOPIK SKRIPSI

Proyek aplikasi OnderdilEngine ini memiliki landasan teknis yang dapat dikembangkan lebih lanjut menjadi topik Skripsi atau Tugas Akhir di tingkat 4 dengan usulan judul:

“Rancang Bangun Sistem Point-of-Sale dan Operasional Bengkel Mobil Menggunakan Arsitektur Zero-Trust dengan Penerapan Algoritma Peramalan Stok Barang dan Audit Trail Anti-Manipulasi”

Rumusan Masalah yang Diusulkan:

  1. Bagaimana merancang struktur pencatatan riwayat transaksi kasir dan servis yang tidak dapat dimanipulasi (anti-tamper log) menggunakan metode verifikasi hash berantai (cryptographic hash chaining)?
  2. Bagaimana menerapkan algoritma peramalan deret waktu (time-series forecasting, seperti Single Exponential Smoothing atau Moving Average) pada data historis transaksi kasir guna memperkirakan kebutuhan stok suku cadang berkala secara akurat?
  3. Bagaimana mendeteksi anomali pada pencatatan transaksi servis (misalnya manipulasi waktu pengerjaan mekanik atau pemberian diskon tidak wajar) menggunakan algoritma pembelajaran mesin (machine learning)?

Rencana Fitur Lanjutan:

  • Integrasi pengingat servis otomatis berbasis pesan WhatsApp ke nomor telepon pelanggan berdasarkan perkiraan jarak tempuh kendaraan (kilometer).
  • Integrasi pembaca data OBD-II melalui koneksi Bluetooth untuk membaca kode kerusakan mobil (Diagnostic Trouble Code) langsung ke formulir keluhan teknis.

8. BUKTI OPERASIONAL DAN IMPLEMENTASI KEAMANAN

Komponen sistem yang telah diuji dan berjalan normal meliputi:

  • Bukti HTTPS & Domain Aktif: Aplikasi telah siap dijalankan pada lingkungan hosting publik menggunakan sertifikat SSL/TLS yang valid.
  • Bukti Fungsi Kasir POS & Cetak Nota: Modul kasir berhasil memproses transaksi suku cadang dan ongkos servis montir secara real-time serta menghasilkan nota siap cetak.
  • Bukti Alur Servis & Peringatan Stok: Status pengerjaan kendaraan dapat diperbarui oleh mekanik, dan master barang otomatis menampilkan penanda peringatan jika stok berada pada batas minimum.

  • Bukti Respon Header Keamanan: Uji respon terminal memastikan server menyertakan header keamanan lengkap untuk mencegah clickjacking dan eksploitasi MIME-type.
9. KENDALA DAN RENCANA PERBAIKAN

• Kendala Teknis yang Berhasil Diatasi:

  • Kompilasi Styling Tailwind v4: Pada saat awal inisialisasi, styling utilitas belum terkompilasi karena Next.js 16 memerlukan konfigurasi khusus PostCSS. Kendala ini diselesaikan dengan menambahkan paket @tailwindcss/postcss dan konfigurasi postcss.config.mjs.
  • Pencegahan Selisih Stok (Race Condition): Untuk mencegah kesalahan pengurangan stok saat beberapa kasir memproses transaksi pada detik yang sama, query database dibungkus ke dalam transaksi atomik prisma.$transaction.

• Rencana Perbaikan Mendatang:

  • Integrasi Pembayaran QRIS: Menambahkan integrasi payment gateway otomatis agar konsumen dapat membayar nota servis melalui scan kode QRIS.
  • Kirim Nota Digital: Mengirimkan struk transaksi dalam bentuk PDF secara langsung ke nomor WhatsApp konsumen sesaat setelah pembayaran selesai.
